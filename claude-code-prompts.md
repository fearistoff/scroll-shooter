# Промпты для Claude Code — пошаговая сборка прототипа

Этот файл — набор готовых промптов, которые копируются в Claude Code **по одному, по порядку**. Рядом должен лежать `game-design-doc.md` — на него ссылаются все промпты.

## Скриншоты-референсы

Скриншоты, на которые ссылается `game-design-doc.md` по номерам (№1–№8), лежат **в корне рабочей директории** под именами `1.png`, `2.png`, …, `8.png`. Номер файла соответствует номеру в ТЗ: №1 = `1.png`, №2 = `2.png` и так далее. Claude Code может открывать их для визуальной сверки механики и раскладки интерфейса.

## Как пользоваться

1. Положите все файлы (`game-design-doc.md`, этот файл и скриншоты `1.png`–`8.png`) в папку проекта.
2. Запустите Claude Code в этой папке.
3. Копируйте промпты **строго по порядку**, по одному за раз.
4. После каждого слоя — откройте в браузере и проверьте по «Критериям готовности» в конце промпта. Не переходите к следующему слою, пока текущий не работает.
5. Если что-то не так — не правьте сами вслепую, а опишите Claude Code, что именно не работает (что видите vs что ожидали).

### Общие правила для всех слоёв (можно вставить один раз в начале сессии)

```
Мы делаем играбельный прототип мобильной crowd-shooter игры на three.js.
Полное ТЗ — в файле game-design-doc.md, прочитай его перед началом.

Правила работы:
- Стек: three.js + TypeScript + Vite. Портретная ориентация (вертикальный экран под телефон).
- Графика на старте — примитивы: капсулы для людей и зомби, боксы для бочек, плоскости для ворот и дороги. Модели добавим позже.
- Пиши модульно: отдельные файлы под сущности (player, enemies, barrels, gates, weapons, world). Не сваливай всё в один файл.
- Много объектов на экране (зомби, пули, кристаллы) — сразу закладывай пулинг/InstancedMesh, не создавай и не удаляй объекты каждый кадр.
- Ввод — pointer-события (работают и на мыши, и на тач).
- После каждого слоя проект должен запускаться и быть играбельным. Не ломай предыдущие слои.
- Все числовые параметры выноси в один конфиг-файл (config.ts), чтобы их было легко крутить.
- Разработка будет вестись по слоям. Каждый слой я буду отправлять в чате. Файл claude-code-prompts.md читать только для понимания плана действий
```

## Слой 0 — Каркас проекта

```
Создай каркас проекта: three.js + TypeScript + Vite.
- Настрой Vite так, чтобы `npm run dev` поднимал локальный сервер.
- Портретный холст (вертикальный), адаптивный под окно, с ограничением по соотношению сторон под телефон.
- Пустая сцена three.js: перспективная камера сверху-сзади под наклоном (обзор дороги), directional + ambient свет, плоскость-«дорога», уходящая вверх.
- Создай config.ts с секцией под будущие параметры (пока можно пустой объект с комментариями по разделам ТЗ).
- Основной game loop (requestAnimationFrame) с фиксированным шагом обновления.

Критерии готовности: `npm run dev` запускается, в браузере видно наклонную дорогу сверху-сзади, окно ресайзится корректно.
```

## Слой 1 — Мир и движение, управление

```
Реализуй "движущийся мир" и управление отрядом (по game-design-doc.md, разделы 3 и 4).
- Отряд стоит на месте в нижней трети экрана. Иллюзия движения: текстура/сегменты дороги и все будущие объекты едут сверху вниз с настраиваемой скоростью (worldSpeed в config.ts). Пока в качестве отряда — одна капсула-заглушка.
- Управление: горизонтальное перетаскивание pointer-ом двигает отряд влево-вправо в пределах ширины дороги. Ограничь движение краями дороги (roadWidth в config.ts).
- Разметка дороги (пунктир по центру) должна визуально прокручиваться вниз, подтверждая движение.

Критерии готовности: капсула-отряд ездит влево-вправо за пальцем/мышью в пределах дороги; разметка дороги прокручивается вниз, создавая ощущение движения вперёд.
```

## Слой 3 — Зомби

```
Добавь обычных зомби (game-design-doc.md, раздел 9).
- Спавн зомби сверху, движение вниз к отряду вместе с миром. Используй InstancedMesh или пул капсул — на экране их может быть много.
- Обычный зомби: HP 3, урон по стрелку 5 (config.ts).
- Пули наносят 1 hp урона зомби; при HP<=0 зомби умирает и уходит в пул.
- Зомби доходят только до линии перед отрядом (не наезжают на него), останавливаются и бьют ближайшего стрелка периодически, пока живы. Пока у героя нет полосы HP — просто выведи его HP числом на экране для отладки.

Критерии готовности: сверху идёт поток зомби; герой их отстреливает (3 попадания = смерть); дошедшие до линии зомби бьют героя, его отладочный HP падает.
```

## Слой 4 — Бочки-бонусы (базово)

```
Добавь бочки-бонусы (game-design-doc.md, раздел 7).
- Бочка едет сверху вниз, над ней число = прочность (HP бочки). Стрельба уменьшает число.
- Трещины/смена вида при 50% и 25% прочности (пока можно менять цвет бокса).
- При прочности <=0 бочка ломается и выдаёт содержимое отряду.
- Уворот: если увести отряд в сторону и не разбить — бочка проезжает мимо, бонус не выдаётся. Контакт целой бочки с отрядом наносит урон стрелкам.
- Пока реализуй два типа содержимого: "смена стрелкового оружия" (меняет оружие у всех — пока заглушка на след. ступень) и "иконка" над бочкой, обозначающая тип.

Критерии готовности: бочка едет вниз с числом прочности, число падает от выстрелов, на 50/25% меняется вид, при 0 — ломается и применяет бонус; мимо можно увернуться; целая бочка при контакте бьёт отряд.
```

## Слой 5 — Отряд и построение

```
Реализуй полноценный отряд (game-design-doc.md, раздел 5).
- Тип бонуса "стрелки" из бочек добавляет доп. стрелков (HP 30 каждый). Иконка количества: до 4 — N фигурок; >4 — 4 фигурки + множитель "xN".
- Построение "клином": 1-й ряд до 4 бойцов, последующие ряды до 7. Главный герой всегда впереди и крупнее.
- Каждый доп. стрелок стреляет тем же общим стрелковым оружием (та же частота/дальность), пули летят вверх.
- Визуальный потолок: после ~6 рядов новых бойцов не рисуем, но общее число выпускаемых снарядов продолжает расти пропорционально "невидимым" стрелкам.
- Урон зомби идёт по ближайшему стрелку; выбитый стрелок (HP<=0) удаляется из строя.

Критерии готовности: сбор стрелков через бочку увеличивает отряд и плотность огня; строй выстраивается клином 4→7; после потолка модели не растут, а плотность пуль растёт; стрелки выбиваются зомби по одному.
```

## Слой 6 — Ворота-множители

```
Добавь оба типа ворот (game-design-doc.md, раздел 8).
Тип A — большая одиночная стена:
- Едет сверху, разделена на секции с числовыми значениями (напр. красная и синяя).
- Стрельба по секции повышает её значение на +1 за попадание.
- Применяется значение ТОЛЬКО той секции, через которую прошёл ГЛАВНЫЙ герой. Плюс — добавить стрелков, минус — удалить (только доп., не героя).
Тип B — колонна малых турникетов:
- Несколько стен подряд с фиксированным значением (напр. "+1" каждая), простреливаются насквозь, от стрельбы значение не меняется.
- Применяет прибавку ЛЮБОЙ прошедший стрелок; проход даёт значение столько раз, сколько турникетов в колонне; стрелков не расходует.

Критерии готовности: у типа A стрельба по секции растит её число, при проходе героя применяется именно его секция (плюс/минус к отряду); у типа B проход отряда через колонну суммирует прибавки без расхода стрелков.
```

## Слой 7 — Оружие полностью

```
Реализуй всю систему оружия (game-design-doc.md, раздел 6).
- Стрелковое (общее на отряд): пистолет 2/с, мини-автомат 5/с, автомат 7/с, пулемёт 15/с — все урон 1 hp, дальность 2/3 экрана. Подбор из бочки меняет оружие у ВСЕХ.
- Особое (заменяет оружие у ОДНОГО стрелка полностью):
  - Огнемёт: 25 снарядов/сек, урон 1 hp, дальность 1/2 обычной.
  - Гранатомёт: 1 выстрел/сек, урон 10 hp.
- Порядок выдачи особого: сначала главный герой, затем доп. стрелки в случайном порядке.
- Все параметры — из config.ts.

Критерии готовности: смена стрелкового оружия меняет темп огня у всего отряда; особое оружие выдаётся сначала герою, потом случайным бойцам, заменяя их оружие; огнемёт бьёт вдвое ближе, гранатомёт — редкие снаряды по 10 hp.
```

## Слой 8 — Мина

```
Добавь бонус "противопехотная мина" (game-design-doc.md, раздел 7).
- Тип содержимого бочки "мина". При получении мины автоматически расставляются примерно на середине поля перед отрядом.
- Через 1–2 сек после расстановки мины активируются (индикация активной мины).
- После активации при приближении ЛЮБОГО зомби детонируют ВСЕ разом.
- Урон по площади: радиус ~2 игровых метра, 20 hp фиксированно, по всем зомби и объектам в зоне. Без гарантированного убийства (крупный зомби может выжить).

Критерии готовности: подбор мины ставит мины на середину поля, через 1–2 с они активируются, при подходе зомби детонируют все сразу и наносят 20 hp по area.
```

## Слой 9 — Крупные зомби и счётчик волны

```
Добавь крупных зомби и счётчик волны (game-design-doc.md, раздел 9).
- Крупный зомби: HP 30 (x10), урон по стрелку 25 (x5), заметно крупнее модель, над ним ВСЕГДА показан числовой запас HP.
- Счётчик волны вверху: полоса с числом = сколько зомби осталось в забеге. Каждый зомби = 1, крупный = 1, босс = 1. Иконка черепа на полосе = в конце будет босс.
- Кристаллы EXP: падают с убитых зомби и разбитых бочек, собираются в счётчик "EXP N" (левый верх). Реализуй пул кристаллов.

Критерии готовности: в потоке встречаются крупные зомби с видимым HP; вверху счётчик оставшихся зомби с черепом; за убийства падают и собираются кристаллы EXP, счётчик EXP растёт.
```

## Слой 10 — Боссфайт

```
Реализуй боссфайт (game-design-doc.md, раздел 10).
- Когда счётчик волны подходит к концу, появляется один босс-гигант.
- Полоса прогресса уровня заменяется многослойной полосой HP босса: суммарно ~1000 hp, разбито на слои (напр. 15–20), каждый слой своего цвета; урон снимает текущий слой, множитель "xN" = сколько слоёв осталось, красное число = суммарное оставшееся HP.
- Босс доезжает до ~1/3 экрана снизу, останавливается, атакует.
- Стрелки во время боссфайта авто-перенаправляют огонь на босса.
- Две атаки: (1) AoE с красным телеграфом-кругом на земле, уклоняемая, 50 hp по попавшим стрелкам; (2) удар по всем сразу, неуклоняемый, 12.5 hp.
- Во время боссфайта бонусы/бочки/ворота не спавнятся.

Критерии готовности: в конце волны выходит босс с многослойной полосой; отряд фокусит огонь; красный круг телеграфит AoE, уводом отряда можно избежать 50 hp; неуклоняемая атака снимает 12.5 hp; убийство босса завершает уровень.
```

## Слой 11 — Мета-петля и экраны (проектируется)

```
Соберём мета-петлю и экраны (game-design-doc.md, раздел 11 — этот раздел мы проектируем сами).
Сначала предложи 2–3 варианта состава экрана прокачки: какие улучшения покупать за EXP (кандидаты: стартовое число стрелков, стартовое оружие, базовый урон/темп, HP героя и стрелков, качество выпадения бонусов). Не пиши код сразу — сперва предложи варианты и дождись моего выбора.
После выбора реализуй:
- Экран результата забега (победа/поражение) с суммой набранного EXP.
- Экран прокачки: трата EXP на выбранные улучшения, сохранение прогресса между забегами (in-memory или localStorage — уточню).
- Переходы: забег → результат → прокачка → новый забег.

Критерии готовности: после забега показывается результат с EXP; на экране прокачки EXP тратится на постоянные улучшения; новый забег стартует с учётом купленных улучшений.
```
